# The HTML renderer and what it can do

The card is not shown in a browser. All My Movies and All My Books render the
template with **THtmlViewer 11.10** (the open-source Delphi HTML component,
<https://github.com/BerndGabriel/HtmlViewer>). It understands HTML 4 and a
useful subset of CSS 2, has no JavaScript, and has its own ideas about a few
things. Knowing them saves hours.

## Not supported at all

`border-radius`, `box-shadow`, `text-shadow`, gradients, `transform`,
`flex`, `grid`, `position: sticky`, `background-size`,
`background-position`, `object-fit`, `calc()`, CSS variables, web fonts
(`@font-face`), media queries, `:hover` on anything but links, JavaScript.
A property the viewer does not know is silently ignored, so the page still
renders - just not the way you meant. Stick to the CSS 2 basics: colours,
borders, padding and margins, fonts, `text-align`, `vertical-align`,
background colour or a single background image.

`background-repeat: repeat-y` / `repeat-x` are treated as `repeat`: an edge
gradient image tiles over the whole box. Use solid colours or a single
non-repeating image.

## Layout: tables, not floats

* **Use tables for columns.** `float: right` with a percentage width is not
  laid out; the "column" spreads over the full page width.
* **`width: 100%` in CSS on a `<table>` is imprecise** (a gap stays on the
  right) and a CSS `width` on a table may be ignored entirely. Give tables
  the HTML attribute as well: `<table width="100%" class="card">`.
* **Percentage `<td>` widths shrink to their content.** Size fixed columns
  in `em`: `td.leftcol { width: 17em }`.
* **Page-wide shrink of percentage tables.** A table with `width: 100%` is
  laid out at about 85% of the available width when (a) a table nested in it
  contains a link with a long `href` - the `url`, `similar`, `trailer` and
  `userfield` placeholders produce those, or (b) a `<div>` with background
  and padding stands right before it. The effect hits every percentage
  table on the page, so when hunting for the culprit change one thing at a
  time. Workarounds: put link-producing placeholders in `<div>` rows rather
  than nested tables, and make the strip before a table a
  `<table width="100%">` instead of a `<div>`.
* `width: 100%` on `<img>` works and is the normal way to size the cover
  inside its box.

## Units and scaling

The program has a card zoom (50-200%: Preferences, group Scale, or
Ctrl+Plus / Ctrl+Minus in the main window) and runs on monitors with
different DPI. How a length reacts depends on its unit:

| unit | DPI scaling by the viewer | card zoom |
|---|---|---|
| `px`, unit-less numbers, HTML `width=`/`height=` attributes | **no** - device pixels | rewritten by the program (px factor = zoom x DPI/96) |
| `pt`, `pc`, `in`, `cm`, `mm` | yes | rewritten by the program (zoom only) |
| `em`, `ex`, `%` | relative, follow the font/parent | not touched - they scale by themselves |

Practical rules:

* Set the base font in `pt` on `body` (`font-size: 11pt`) and everything
  else in `em`. The whole card then follows both the zoom and the DPI.
* `font-size` **without a unit means px** in this viewer, not a multiplier.
* Widths that must grow with the zoom (the cover box, fixed columns) go in
  `em`; widths that must stay a share of the window (`width="100%"`) go in
  `%`. Screenshots sized with `<!--#screenshots width="40%" -->` do not
  grow with the zoom; `width="320"` does.
* Images inside the template (backgrounds, frames, icons) are resampled by
  the program once per template to the current zoom; you do not need to
  ship several sizes.

## Images

* The cover: `<IMG SRC="_cover_" ID="cover">`, exactly that `SRC`. The
  program replaces it with a per-record name so that the viewer's image
  cache never shows the cover of the previous record, then feeds the image
  scaled to the box your CSS gives it (Lanczos resampling; the viewer's own
  stretching is nearest-neighbour and looks bad). Give the box a size: a
  width in `em` or `%`, height by proportion.
* Screenshots: prefer `<!--#screennum1 width="320" -->` over the older
  `<IMG SRC="_screenshot0_">` for the same cache reason.
* Stars, hearts, check marks and the Play button are generated by the
  program from the PNG files in the template folder (falling back to the
  shared `moviecards`/`bookcards` folder) and already scaled.
* Relative paths in `src` and `url()` are resolved from the template folder;
  keep assets in a subfolder (`img/`, `images/`) next to `template.html`.
* Animated GIFs play. PNG alpha works.

## Placeholders are server-side includes

`<!--#name -->` is THtmlViewer's include syntax: the program is asked for
the text to insert at that spot. Consequences:

* The syntax is `<!--#name -->` and `<!--#name attr="value" -->`: a space
  before `-->`, attributes in double quotes. Names are matched
  case-insensitively, but the empty-field check compares the exact text of
  the placeholder, so write them the way the docs spell them.
* The inserted text is HTML, not plain text. Many fields come back as
  links (`<a href="...">Drama</a>`), actors as a `<table class="actors_table">`
  unless the template starts with `<!--#forceplainactors -->`, audio
  tracks as `<ul class="audiostreams">`, episodes inside
  `<div class="episode">`. Style those classes; do not wrap the placeholder
  in another `<a>`.
* Empty values remove the whole source line - see
  [empty-fields.md](empty-fields.md).

## File format

`template.html` in its own folder under `moviecards\` or `bookcards\`, next
to the program. The folder name is what appears in the menu. Encoding: UTF-8;
**with a BOM if the file contains anything beyond ASCII** (comments in your
language, typographic quotes), otherwise the text is read in the system code
page and comes out as garbage. Line endings do not matter, but remember that
the empty-field logic works per line.

A folder named `_old`, or any folder without `template.html`, is ignored.

## Interaction that comes for free

Clicking a genre, an actor, a year, a studio or a personal mark filters the
list by that value; hovering a person shows a photo hint; clicking the
"no cover" placeholder starts an online cover search; `<!--#url -->` opens
the movie page; `<!--#playbutton -->` starts the file. None of this needs
anything in the template.
